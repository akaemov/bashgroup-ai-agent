# Подгружаемый контекст для агента разведки объектов

**Цель:** использовать весь накопленный объём знаний, не вставляя его целиком в промпт и не позволяя агенту додумывать факты.

## Принцип работы

Агент не получает весь архив одним сообщением. Перед запуском он всегда получает компактный стартовый контекст, а затем подгружает только те материалы, которые относятся к задаче или найденному объекту.

Подгрузка происходит не по ощущению «контекста мало», а по явным признакам в запросе и в найденном объекте.

## Слои контекста

### 1. Всегда загружается

Короткая стартовая карточка:

- кто такая БАШГРУПП;
- заказчики;
- география;
- типы объектов;
- продуктовая карта и поисковые термины;
- производственные приоритеты;
- критерии интересного объекта и стоп-факторы;
- формат доказательств в отчёте.

Этот слой помогает агенту сформировать запросы и первично отсеять нерелевантные находки.

### 2. Загружается по параметрам запуска

При каждом запуске добавляются временные настройки:

- период и география поиска;
- продуктовый фокус;
- типы объектов и заказчиков;
- специальные цели: например, загрузка Grigliato или поиск фасадных проектов;
- пороги и исключения;
- список активных источников из реестра.

### 3. Подгружается по признакам найденного объекта

После первичного нахождения объекта агент извлекает только подходящие сведения:

- упомянут потолок, рейка, фасад, перфорация или экран — загружается соответствующая карточка продуктового направления;
- найден тип объекта: школа, БЦ, медицина, ЦОД, ЖК — загружается карта сегмента и релевантные кейсы;
- объект в конкретном городе — подгружаются правила географии, логистики, местные партнёры и референсы;
- есть признаки нестандарта — подгружаются ограничения производства и правило эскалации человеку;
- объект похож на портфельный кейс — подгружается подтверждённый кейс, а не весь архив портфолио.

### 4. Подгружается для проверки вывода

Перед включением объекта в отчёт агент извлекает только материалы, нужные для проверки:

- источники стадии и срока;
- сведения об участниках;
- подтверждение продуктовой релевантности;
- правила приоритета и стоп-факторы;
- при необходимости — актуальный статус документа, каталога или сертификата.

## Критерии подгрузки

Для каждого материала в базе должны быть метаданные:

- тема: продукт, сегмент, регион, роль заказчика, стадия, технология;
- тип: карточка продукта, кейс, производственное ограничение, правило, источник, портфолио;
- дата и срок актуальности;
- уровень доступа: публичный, внутренний, ограниченный;
- ключевые слова и синонимы;
- ссылка на первоисточник;
- статус: актуален, требует проверки, архив.

Агент сначала определяет сущности в задаче и находке — например «Казань», «школа», «кубообразная рейка», «чистовая отделка» — и по этим меткам выбирает документы для подгрузки.

## Как использовать много информации без галлюцинаций

1. **Хранить знания дробно.** Не один большой файл «всё о компании», а отдельные карточки продуктов, сегментов, регионов, кейсов и ограничений.
2. **Иметь один источник истины.** Для каждого факта известны владелец, дата проверки и первоисточник.
3. **Не смешивать факт, гипотезу и рекомендацию.** Агент обязан маркировать каждое утверждение.
4. **Не отвечать при нехватке доказательств.** Вместо догадки агент пишет, каких данных не хватает и что нужно проверить.
5. **Проверять свежесть.** Устаревший каталог, сертификат или прайс не используется как актуальный факт.
6. **Фильтровать по доступу.** Внешний отчёт не получает внутренние цены, КП, договоры и иные закрытые материалы.
7. **Прикладывать доказательство к выводу.** Каждый объект в отчёте содержит ссылку, дату, источник и степень уверенности.

## Роль реестра источников

Реестр источников определяет, **где** агент ищет сигналы. Контекст компании определяет, **что** считать ценным. Материалы из базы помогают понять, **почему** конкретный объект релевантен.

Агент может находить новые полезные сайты и каналы, но сначала добавляет их в реестр как `кандидат`. После проверки человеком источник становится `активен` и участвует в регулярном поиске.

## Пример одного цикла

1. Запуск: «за неделю найти проекты в Уфе и Казани для потолочных и фасадных решений».
2. Агент получает стартовую карточку, географию, продуктовый фокус и активные источники.
3. Находит публикацию о бизнес-центре на стадии проектирования.
4. Распознаёт: БЦ, Уфа, ранняя стадия, фасад/потолок, застройщик и архитектор.
5. Подгружает карточки «БЦ», «фасады», «потолки», правила Уфы, подходящие кейсы и критерии интересного объекта.
6. Проверяет источники и формирует находку только с подтверждёнными фактами.
7. Если данных о стадии или объёме нет, помечает это как пробел, а не додумывает.

## Что нужно подготовить постепенно

- карточки продуктовых направлений;
- карточки сегментов объектов;
- правила по регионам;
- структурированное портфолио и кейсы;
- реестр производственных возможностей и ограничений;
- расширяемый реестр источников;
- правила свежести, владельцев данных и уровней доступа.
